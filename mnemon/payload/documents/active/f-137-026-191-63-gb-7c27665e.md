# F 盘全盘只读盘点与虚拟整理方案

## 任务与约束

- 2026-11-13 执行：对 `F:\` 全盘做**只读扫描 + 虚拟归类**，未修改、未移动、未重命名、未删除 F 盘任何文件；只枚举元数据，另抽样读取文档正文。
- 范围排除 4 个系统目录：`$RECYCLE.BIN`、`System Volume Information`、`.Spotlight-V100`、`.fseventsd`。
- 方法边界（写进报告正文，避免被误读为逐字比对）：分类依据以目录结构、文件名、类型、大小、修改时间等元数据为主，另抽取 200 余份 docx/PDF（规划文本、说明书、评估报告）核对正文语义；未逐字读取全部 191.63 GB，逐文件判定以元数据为准。
- 交付形态是**搬迁方案**而非执行结果：先出虚拟清单，确认后按「先建骨架、分批迁移、重复最后处理」落地，主要动机之一是规避 Windows 260 字符路径限制。

## 现状诊断（6 条，报告第二节）

1. **四个板块混在盘根**：审查按地市、编制按县区、评估按县市、通则按「政策—试点—课题」建目录，四套命名互不兼容；`标准`、`相关附件`、`淳安乡镇20240315` 等 214 个文件 / 10.25 GB 直接堆在地区根目录。
2. **版本目录多代并存**：余杭 8 套数据库相关目录（`数据库`、`0113数据库`、`0620修改`、`0708`、`0812数据库`、`0905径山数据库修改`、`1202数据库3+x`、`_2024年4月版本`）合计 56,460 个文件 / 16.49 GB，仅靠日期和「修改/干净版」区分，无版本说明文件；淳安同样有 `前一阶段成果`、`20240422淳安乡镇成果`、`1208对接` 多代。
3. **重复副本被数据库内部文件放大**：同名+同大小粗筛得 8,113 组、105,572 个多余副本、约 16.4 GB；剔除 `.gdb` 内部文件与 DataCheck 临时目录、限定单文件 ≥1 MB 后为 669 组 / 886 个 / 约 11.2 GB。
4. **路径过深过长**：最长 215 字符已接近 260 上限，整体搬迁有失败风险；建议 Robocopy `\\?\` 长路径模式，或先迁浅层目录。
5. **临时/锁文件残留 47 个**：`~$` Office 锁文件 26（其中 4 个在 F 盘根目录、对应原文件已不存在）、`Thumbs.db` 15、WPS 临时 3、`.tmp` 2、`.DS_Store` 1。
6. **命名噪声**：含「副本/(1)/最终/最新/修改/改/v2/copy」的 500 个，无扩展名 786 个，另有 `0000-改.docx`、`001.rar`、`无标题.mxd`、`新建文件夹` 等无信息量命名。

## 虚拟分类体系

四层：**板块 → 地区/项目 → 工作阶段 → 原始目录**。前两层定「哪个项目」，第三层定「哪一步」，第四层保留原目录名，使任何文件都能沿虚拟路径反查原始位置。

```
F盘虚拟整理/
├─ 01_乡镇总规审查/  00_制度与标准 + 01_杭州…08_宁波，
│    每市下 10_收件 / 20_审查意见 / 30_报批与备案 / 40_标准与模板 / 50_项目与合同
├─ 02_乡镇总规编制/  01_余杭 / 02_淳安 / 03_其他地区，
│    每县下 10_基础资料 / 20_数据库与版本 / 30_方案与汇报 / 40_成果与报批 / 50_项目综合
├─ 03_总规实施评估/  00_导则与政策 / 20_数据与附件 / 30_省域报告与交流 / 01_普陀…09_温岭与富阳
├─ 04_乡村地区通则研究/  10_政策依据 / 20_规定与过程稿 / 30_试点案例{松阳,兰溪,永嘉,海宁,缙云,龙泉} / 40_课题研究 / 50_汇报与解读
├─ 05_公共支撑/  10_省级技术标准 / 20_软件与工具
└─ 99_待清理/  10_临时与锁文件 / 20_重复副本候选 / 30_系统目录说明
```

阶段判定规则按目录名关键词、优先级从高到低（报告第三节表格）：

- 审查：50 招投标/合同/任务书/采购/磋商/建议书 → 40 模板/指南/标准/审查表 → 30 报批/批复/备案/汇交/归档/终稿 → 20 审查意见/复核/质检/核查/汇总 → 默认 10 收件。
- 余杭编制：50 合同类 → 40 归档/干净版/报批/终稿/交接/成果 → 30 汇报/人大/公示/方案/文本/图集/PPT/对接 → 10 收集/资料/底图/现状/三调/边界/地形 → 默认 20 数据库与版本。
- 淳安编制：50 合同类 → 40 成果/提交/报批/终稿/归档 → 30 汇报/调研/会议/对接/座谈/PPT → 20 数据库/gdb/数据/矢量/版本 → 默认 10 基础资料。

体量集中在少数目录，映射表按原始目录聚合（报告 4.1–4.4，XLSX「目录映射」161 行）：杭州 50.82 GB、丽水 44.86 GB、鄞州 15.88 GB、舟山定海 8.03 GB 四地占审查板块 93%；余杭 63,343 个 / 34.54 GB（其中 8 套版本目录 56,460 个 / 16.49 GB，单 `数据库` 一目录 18,137 个 / 5.13 GB）；淳安 2,246 个 / 19.72 GB，主要为 `前一阶段成果`、`1208对接`、`20240422` 与 20240315 成果。注意：报告映射表按**原始目录**统计，已调往 `99_待清理` 与 `05_公共支撑` 的少量文件会让分项合计略高于虚拟总量，正文已加注说明。

## 重复与清理口径（有意的保守边界）

- 只做「同名 + 同大小」粗筛，**未做哈希**；删除前须对 669 组做 SHA-256 复核，优先保留路径最短或位于 `40_成果与报批` / `30_报批与备案` 的那一份。
- 典型大件：`规划图集.pdf` 890 MB × 2、`02【瓶窑西】技术文件.pdf` 599 MB × 2、`姜家镇pdf(1).zip` 331 MB × 2、`鸬鸟镇规划公示材料.pdf` 79 MB × 5。
- 47 个临时/锁文件可先直接清理（合计仅 1.9 MB），价值在消除「文件还在编辑」的错觉而非省空间。
- 报告另指出 `$RECYCLE.BIN` 中还有 9,377 个文件 / 约 34.9 GB 未纳入本次整理，清空回收站是单项收益最大的操作；该数字来自一次性盘点，本次未复扫。

## 校验与可复现

生成与校验脚本都在 `_fscan/`（`stats2.py`、`stats3.py` 做统计，`make_report.py` 425 行负责 md/xlsx/csv 三件产物，`patch*.py` 是分块补丁，`validate.py` 收尾校验）；每轮重跑都打印相同汇总（`files 137026 GB 191.63 dups 886 temp 47 key 34`），可据此判断报告未被改坏。

`validate.py` 实测结果：CSV 137,026 行 × 11 列、虚拟路径为空 0、异常路径 0；动作分布 归档 136,093 / 建议删除（重复副本）886 / 建议删除 47；板块分布与报告合计一致；md 8 个章节标题齐全、无 `None` 泄漏、289 行 / 约 14.5 KB；最长路径 215 字符。XLSX 共 8 表：总览、分类体系、目录映射（161 行）、重点成果（34 条）、重复与临时（107 条）、类型统计（41）、年度分布（13）、待确认（8 条）。
