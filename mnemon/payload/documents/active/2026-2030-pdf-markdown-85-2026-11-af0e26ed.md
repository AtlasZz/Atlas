## Windows.Data.Pdf 调用坑（Playwright/第三方库不可用时的首选）

- **`LoadFromFileAsync` 不吃路径字符串**：直接传 `"D:\...\x.pdf"` 抛 `The parameter is incorrect. inputFile`（ArgumentException）。必须先 `[Windows.Storage.StorageFile]::GetFileFromPathAsync($path)` 拿 StorageFile，再传入；等价地也可用 `IRandomAccessStream`。
- **WinRT 异步要自己抽**：脚本里定义 `Await` 帮助函数（`AsTask()` + `$task.Wait(-1)`），否则拿到的是未完成的 IAsyncOperation。首版在 `$task.Wait(-1)` 处报 `AggregateException`，真实原因被包在外层，要展开看内层异常才知道是 inputFile 参数问题。
- **没有 `Close()` 方法**：`PdfDocument` 与 `PdfPage` 都**不含** `Close`（`MethodNotFound`），只有 `Dispose()`；逐页循环里 `$page.Close()` 会让每页都抛一次非终止异常，PNG 仍能写出，但日志被刷满——建议 `$reader.Dispose(); $stream.Dispose(); $page.Dispose()`。
- 渲染尺寸：`$page.RenderToStreamAsync($stream, $opts)` 里设 `DestinationWidth/Height`；本轮输出 2400×1350，足够 VLM 读小字表格。
- 校验页码：先打印 `PAGECOUNT`（本轮 85）再循环，避免渲染脚本静默少页。

## 环境坑

- MSYS Bash 里 **没有 perl**（某次管道命令报 `line 3: perl: command not found`，exit 127）；文本批处理改用 Python 或 PowerShell，别假设 perl/sed -i 可用。
