# 中文公文 PDF→Markdown 版面重建（pdf2md.py）

记录时间 2026-11-09。工作目录 `D:\Workspace\DSHarness`。任务：把桌面上的中文公文 `关于进一步.pdf`（《关于进一步规范国土空间总体规划实施体检评估和动态维护方案编制审查工作的通知》，13 页）转成结构化 Markdown。

## 结论

- markitdown 能跑通，但产物质量不可用；改用 pdfplumber 逐页做版面重建，自建 `.work/pdf2md.py`（约 350 行），只改路径即可复用于同类公文。
- 产出 `关于进一步.md`：273 行 / 20,417 字节 / 75 个内容块 / 22 个标题；附件 1、3、5 的合并单元格表格、竖排表头、目录树均还原。
- 该 PDF 有完整文本层（`/Font` 125 处、`/Image` 0、`/DCTDecode` 0；13 页字符 `upright` 全 True），全程未走 OCR。

## 环境与工具链坑

- 沙箱拒绝 uv 写用户目录锁文件：`failed to open file C:\Users\zhouy\AppData\Roaming\uv\tools\.lock: 拒绝访问 (os error 5)`。解法是把 `UV_CACHE_DIR` / `UV_PYTHON_INSTALL_DIR` / `UV_TOOL_DIR` 三个变量全部重定向到工作区内目录。
- `uvx markitdown` 只装核心包，PDF 解析器在 extra 里，报 `MissingDependencyException ... include the optional dependency [pdf] or [all]`。必须用 `uvx --from "markitdown[pdf]" markitdown <in.pdf> -o out.md`。
- markitdown 产物（25,760 字节）的三处硬伤：正文按 PDF 行硬折行（一句被切成三四行）；合并单元格表格被拆成碎片 pipe 表（出现 `| 联 | …`、`| 性 辑 与动态维 |`）；竖排栏位文字乱序（「逻联辑性关」）。原始输出留档 `.work/关于进一步.raw.md` 只作字符覆盖对照，不作成品。

## 版面重建五段核心逻辑

1. **`extract_cell(page, bbox)`**：只取字符中心落在 bbox 内的字符；若"行簇数 == 字符数且字符数 ≥ 3"判为竖排 → 按 x0 聚成列、**从右到左**读列、列内按 top 读；否则按平均字宽分行、行内按 x0 拼接。前提结论：本文档竖排不是旋转字，而是逐字定位，只能靠几何聚类还原——「逻辑关联性」在表头格内表现为 x0=90.3 的"逻辑关" + x0=78.3 的"联性"，右列先读。
2. **`render_table`**：补空列 → 首列向下填充（仅当第 2/3 列有内容，避免把残行误填）→ 折叠多级表头（首列重复如"序号"，或 `_is_headerish()` 判定的短标签行：≤8 个非空格、单格 ≤22 字、不含句读）→ 单格整行提升为表题。
3. **`merge_tables`**：跨页续接；丢全空行、丢重复表头；首列为空但其余有内容的续行并回上一行，按有无句末标点决定直连还是 `<br>`。纵向合并会让首列为空，所以**只能丢"全空行"**，否则会整条丢掉"方案已（未）通过数据库质量检查…"。
4. **块分类与优先级**：`附件 N` / `一、` / `（一）` 判标题；`附件：1. …` 附件清单必须**先于**表题判断，且表题要求前置段落为空；表题需短、无句末标点、以"表/台账"结尾并排除"代表/填表"；目录树单独设为 `tree` 块，按 x0 层级输出代码块。
5. **分段**：编号行且 x0 与前行一致 → 断段；前行以句末标点结尾且（有缩进 或 右边界明显偏左）→ 断段。强表题（`表\d+：`）无条件断段。

## 迭代中修掉的典型 bug

| 现象 | 原因与修法 |
| --- | --- |
| "方案已（未）通过数据库质量检查…"整行消失 | 纵向合并导致首列为空，旧逻辑当空行丢了 → 仅"全空行"才丢 |
| 4 层表头被当数据行（表 1 出现三行"序号"） | 改为先向下填充再折叠，并新增 `_is_headerish()` 判定 |
| "（一）市级审查表"被加粗成表题 | 判断顺序错，`is_heading` 必须优先 |
| "附件：1. 市级审查意见表<br>2. …"整串被并进表题 | `RE_ATTACH` 要先判，且表题判定需前置段落为空 |
| "示例 1-201-3，其中…201 代表…"被当表题 | 追加排除"代表/填表"结尾 |
| 目录树被压成一行，树里的 201/202/104/105 被当页码删掉 | 加 `tree` 块类型按 x0 层级输出代码块 + 页码过滤只对 `y > 0.88 × 页高` 生效 |
| 表 3 标题被粘进上一条备注末尾 | 强表题（`表\d+：`）无条件断段 |

## 校验方法（可复用）

- **结构核对**：导出全部 heading 逐条对源文件。本例 22 个：总标题、正文（一）～（五）、附件 1/2/3/5、附件 2 的（一）～（七）。
- **字符覆盖比对**：raw 与成品的中文 Counter 相减。raw 4658 字 vs 成品 4956 字，缺 16 字（材料/编码/序号/附件等重复表头），属去重预期，无实质丢失。
- **人眼抽读**：1–100 行、160–217 行、219–273 行，附件 1 表格逐行，附件 3 编码 1-201-X～4-B21-X 全条核对。
- 页码过滤若不限定 `y > 0.88 × 页高`，目录树里的 201/202/104/105 会被当页码删掉——这是本轮唯一一次"看起来像丢内容"的假警报。

## 源文件自身的缺陷（不是转换丢失）

- 页码印到 31，实际只有 13 页（前 10 页 A4 纵向 595.3×841.9，后 3 页横向 842×595），属节选装订。
- 附件 3 第 8→9 页处缺 2-106-X 行前半段，成品按原样保留残句，未编造补全。
