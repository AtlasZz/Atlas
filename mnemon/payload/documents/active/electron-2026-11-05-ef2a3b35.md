# 内置浏览器 Electron 运行时下载超时：根因、镜像修复与验证

日期：2026-11-05　环境：Windows，DSH Web（127.0.0.1:51975），profile 为 `desktop`：`C:\Users\ZY-WORK\.dsh\profiles\desktop`。

## 症状

设置 → 浏览器 → 就绪状态里点“准备内置浏览器”后，Electron 准备失败（面板展示 provisioning 未完成/可重试），内置浏览器载体不可用。表现为“插件像坏了”，但插件代码本身正常。

## 根因（设计使然 + 网络条件）

- 插件 `dsh-builtin-browser` 0.5.6 刻意不在安装阶段下载 Electron（issue #41：postinstall 里放 ~100 MB 下载会被 pnpm 默认 `strict-dep-builds` 拦掉，且下载失败会连带整个安装失败）。下载被推迟到“首次需要且选择内置载体”时，在后台进行，失败不致命。
- 该下载有写死的硬超时：`lib/browser-electron/electron-provision.js` 第 36 行 `export const PROVISION_TIMEOUT_MS = 180_000;`，无配置项。超过 180 秒即判定失败，并给出指向 Settings 重试或 `npx --no dsh-browser-install-electron` 的提示。
- 本机修复前 `node_modules/electron` 只有包、没有 `dist/` 与 `path.txt`，`%LOCALAPPDATA%\electron\Cache` 也不存在，即必须下载约 158 MB 的 `electron-v44.10.2-win32-x64.zip`。

## 实测证据

| 源 | 结果 |
|---|---|
| GitHub release-assets（默认） | 20.4 秒仅 785 KB（约 39 KB/s），推算 158 MB 需接近 1 小时 |
| npmmirror 镜像 `https://npmmirror.com/mirrors/electron/` | 158 MB / 6.3 秒（约 25 MB/s） |

结论：默认源不可能在 180 秒内完成，所以无论重试多少次“准备内置浏览器”都只会超时，与面板文案完全对应。

## 修复步骤（不修改插件代码）

用镜像执行插件自带的安装脚本（`scripts/install-electron.mjs` → electron `install.js`，含 SHA256 校验）：

```
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node .../node_modules/electron/install.js
```

本次结果：`exit=0 elapsed=10s`；`dist/` 73 个文件、367.6 MB；`dist/version = 44.10.2`；`path.txt = electron.exe`。

## 验证

- `runtime-status` 路由返回：`{"readiness":"ready","carrier":"bundled","electron":{"state":"present"},"canProvision":false}`。
- 实际用内置浏览器打开 `https://example.com`，标题 `Example Domain`，CDP 正常。
- 面板会缓存上一次失败结论，需在“就绪状态”点一次“重新检测”才会刷新为可用。
- 同接口中 `bridge: {present:false}` 属预期：本机是 `dsh web`、未安装 DSH Desktop，没有桌面侧栏桥；内置载体只依赖 Electron 本身。

## 预防

插件升级或 Electron 主版本变化会重新下载，仍会撞上 180 秒上限。建议设置用户级环境变量后重启 DSH：

```powershell
setx ELECTRON_MIRROR "https://npmmirror.com/mirrors/electron/"
```

或显式设置 `ELECTRON_PATH` 指向可 spawn 的 electron 二进制。

## 相关实现要点（便于后续定位）

- `resolveElectronPathImpl` 的解析顺序：`ELECTRON_PATH` 覆盖 → 插件自带 electron 包（纯文件探测，绝不 `require('electron')`，避免 Electron 44+ 在 require 时触发下载）→ DSH 安装锚点（新的优先）→ 进程本身即裸 Electron（打包的 `DSH Desktop.exe` 不可复用）→ 进程祖先链 → 抛错。
- 错误文案会明确给出 `npx --no dsh-browser-install-electron`、`ELECTRON_PATH` 和“下载可能仍在进行”的解释，排查时优先看 Settings → Browser → Readiness 的状态机。
- 启动子进程时 `env` 会删除 `ELECTRON_RUN_AS_NODE` 与 `NODE_OPTIONS`；而 provisioning 自身相反，用 `ELECTRON_RUN_AS_NODE=1` 以 node 方式跑 `install.js`。
